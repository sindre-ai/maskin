# A Field Written to `workspaces.settings` but Not Modelled in the Strict Settings Schema

- **What**: `workspaceSettingsSchema` (`packages/shared/src/schemas/workspaces.ts`) is built from `.strict()` objects, so an unmodelled key does not get *stripped* — it fails the **whole** parse. Nothing on the write path notices, because the routes that own these sub-objects write the raw settings row directly (`/api/claude-oauth`, by design: PATCH `/api/workspaces/:id` rejects `claude_oauth` outright). What breaks is every unrelated READER that parses the whole settings object and shrugs off a failure: `routes/billing.ts` does `settingsParse.success ? settingsParse.data.billing : undefined`, so one unmodelled key in `claude_oauth` makes `billing` read back as *absent* — the workspace is quietly "not eligible to buy usage credits", its plan cap misreads, and no error is raised anywhere. The blast radius is unrelated to the feature that added the field.
- **When to check**: Any time you persist a new key into `workspaces.settings` — including a new field inside an existing sub-object like `claude_oauth`, `billing`, or `custom_llm`, and including one written by a route that (correctly) bypasses `PATCH /api/workspaces`. The write succeeding and the feature working end-to-end proves nothing about the schema.
- **Fix pattern**: Add the field to `workspaceSettingsSchema` in the same commit as the code that writes it. Where the value is open-ended (ids generated at runtime, say) model it as a `z.record()` with a key regex rather than leaving it out. Assert it with an integration test that performs the real write and then runs `workspaceSettingsSchema.partial().safeParse()` over the stored row — `apps/dev/src/__tests__/integration/claude-oauth-routes-slots.test.ts` (`keeps every stored slot parseable by the workspace settings schema`) is the shape to copy. A mocked-DB route test cannot catch this: it never round-trips through the row.
- **History**: The Claude subscription slot `nickname` shipped as a stored field but was never added to `claudeOAuthLegacySlotSchema`, so from the moment a customer named a subscription, every `workspaceSettingsSchema` parse for that workspace failed and its `billing` block read as undefined on the credit-checkout and plan-cap paths. Found and fixed 2026-09-03 alongside the N-subscription work.
