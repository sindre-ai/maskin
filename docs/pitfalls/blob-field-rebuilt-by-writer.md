# A Non-Token Field on a Record That Some Writer Rebuilds From Scratch

- **What**: `claude_oauth`'s slot blob is written **wholesale** by several paths — a token refresh (`persistRefreshedSlot`), an import, a promote. Any field on that record which is not token material (`nickname`, and now the Anthropic `account` identity) is therefore deleted by any writer that rebuilds the record from its own inputs rather than merging onto what is stored. There is no error and no failed write: the credential keeps working, and only the label vanishes — days later, on whatever unrelated event happens to trigger a rewrite. That delay is what makes it hard to report: the customer sees "the nickname disappears once in a while", not "replacing my credentials clears the name".
- **When to check**: Any time you add a field to a record that is persisted as one blob, and any time you write such a blob from a function whose job is only one of the fields. Grep for every writer of the record (`writeSlot(`, `encryptOAuthTokens(`) — not just the one you are editing — and ask of each: does this caller know about the field I just added? A field added to the TypeScript interface alone is invisible to a function that builds the object literal by hand.
- **Fix pattern**: Merge display/metadata fields at the write boundary instead of trusting every caller to carry them — `preserveSlotLabels(incoming, stored)` in `apps/dev/src/lib/claude-oauth.ts` does this, with an incoming value still winning so a deliberate rename works. Then fix the rebuilders themselves too (`refreshClaudeToken` now carries `nickname` and `account`), because the boundary can only preserve what is already stored. Cover it with a test per writer, not one per field: the integration tests `keeps the slot nickname when a token refresh is persisted over it` and `keeps a slot nickname across a credential replacement` each pin a different writer.
- **History**: Three independent instances of the same bug for one field. (1) `refreshClaudeToken` rebuilt the token record field by field and dropped `nickname`, so a name survived only until its subscription's next token refresh. (2) `POST /api/claude-oauth/import` wrote `encryptOAuthTokens(body)` straight over the slot, so re-pasting credentials for an expiring subscription — the most common reason to visit that route — silently cleared the name. (3) On the frontend, a `useEffect` synced the nickname input from the server on every status refetch, wiping whatever the user was mid-way through typing when any sibling mutation on the page invalidated the query. Fixed 2026-09-03; (1) and (2) share the boundary fix above, (3) guards the sync while the field is being edited.
