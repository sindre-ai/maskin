# A Successful Turn Whose "Reply" Is the Model Narrating Tool Calls It Never Made

- **What**: A model that loses the tool-call channel sometimes serialises its intent as prose wrapped in invented XML-ish tags — `<skill_called>`, `<tool_call>`, `<function_calls>` — including arguments and the results it *expected* to get back. The CLI closes the turn on that text with `is_error: false`, so every error path stays quiet: `classifyTurnError` never runs, no replay is attempted, and `InteractiveTurnFinalizer` posts the text into the human's chat verbatim because its only content guard was "is it empty". The human sees a wall of fake tool calls, the model's own notes to itself, and — because the monologue is unfiltered — internal identifiers and the agent's container paths. Nothing ran: the tools the turn was about were never called, so the reply is not merely ugly, it is absent.
- **When to check**: Any code path that takes model-authored text and puts it in front of a human without a schema between them — the interactive chat finalizer, comment bodies, PR descriptions, anything posted from a `result` envelope. Also whenever a workspace can fall back to a non-Claude model: this failure is rare on Claude and common on weaker routes, so it shows up first in workspaces with no `claude_oauth` credentials, where `llm_route` degrades to whatever OpenRouter picks.
- **Fix pattern**: Detect it and **ask the model to redo the turn** rather than stripping the markup or dropping the message. Stripping posts whatever prose survived (in the observed case one sentence, "Past the timeout window — checking status.") as though it were a finished answer, while the work it describes still has not happened; dropping leaves the human in silence. `apps/dev/src/lib/pseudo-tool-call.ts` does the detection — several tag occurrences AND almost nothing outside their span, so a genuine answer that quotes the syntax still posts — and `InteractiveTurnFinalizer.handlePseudoToolCallTurn` writes one correction back to stdin, reusing the existing replay watchdog so a correction that never comes back still reaches the human. Budget the correction **per session, not per turn payload**: the correction is itself a new user turn, so a payload-keyed counter (the shape `retryCounts` uses for API failures) would start fresh every time and nudge forever.
- **History**: Reported by a customer 2026-08-31 as "agent is outputting some thing that looks like internal things from the session". Mesh Firm session `c37fc7da`, log `3848084` at 13:17:19Z: a Chief of Staff turn on the fallback route (`deepseek-v4-flash` via provider `Relace`) closed with 74 `<skill_called>` tags narrating a `get_session` call it never made, plus `/home/agent/.claude/projects/-agent-workspace/088a9cc6…/tool-results/call_6706….json`. `is_error` was false and the turn cost $4.63. Same underlying cause as the `get_actor` entry above — the workspace had no Claude credentials — but a different failure: there the model misread a good response, here it produced a bad one.
