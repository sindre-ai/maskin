# A Frontend Observability SDK That Is Tree-Shaken Out of the Production Bundle

- **What**: `apps/web`'s SDK modules gate on a `VITE_` config var — `if (!dsn || !enabled) return` in `lib/sentry.ts`, `if (!url || !enabled) return` in `lib/faro.ts`. Vite **statically substitutes** `import.meta.env.VITE_*` at build time, so when the var is unset the condition folds to a constant, Rollup eliminates the `init()` call as dead code, and the entire SDK is dropped from the bundle. The build succeeds, `pnpm test` passes, the module still exists in source, and every code review reads as "Sentry is wired up" — but the shipped bundle contains no reporting code at all. It is indistinguishable from a working setup unless you query the destination or grep the built artefact.
- **When to check**: Any time you add or rely on a `VITE_`-gated SDK, and *specifically* whenever you add a `VITE_` var. `turbo.json` `globalPassThroughEnv` is necessary but **not sufficient** — the production SPA is built inside `apps/dev/Dockerfile`, which only sees `VITE_` vars that have an explicit `ARG` + `ENV` pair before the `turbo run build --filter=@maskin/web` step. A var present in `.env` and in `turbo.json` but missing from the Dockerfile is silently empty at image build time.
- **Fix pattern**: Add the `ARG`/`ENV` pair to `apps/dev/Dockerfile` alongside the existing `VITE_POSTHOG_*` ones, and verify against the built artefact, not the source: `grep -c "grafana" apps/web/dist/assets/*.js` (or `"sentry"`) must be non-zero. Then confirm by query — throw a deliberate error in a preview build and check the payload actually arrives. Same "verify by query, not by status" discipline as the Alloy entry above.
- **History**: Found 2026-08-27 while adding Grafana Faro. `VITE_SENTRY_DSN` was in `turbo.json` `globalPassThroughEnv` but had never been added to `apps/dev/Dockerfile`, so `@sentry/react` had been tree-shaken out of every production image since the frontend Sentry integration landed — the browser half of Sentry was reporting nothing the whole time. Measured directly: a build with no `VITE_SENTRY_DSN` yields 704,745 gzipped JS bytes and zero `sentry` string matches; the same build with the DSN set yields 735,138 bytes and six matches.
