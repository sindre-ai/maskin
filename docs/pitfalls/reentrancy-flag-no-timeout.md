# A Re-Entrancy Flag With No Timeout Turns One Hung Await Into a Global Outage

- **What**: `SessionDispatchQueue.tick()` guards itself with `if (this.running) return` and clears the flag in `finally`. That is correct only if every awaited call inside the batch eventually settles. One that never does — here a DB query on a pooler connection that died silently during a deploy — leaves `running` pinned to `true`, so every later tick returns immediately. Nothing throws and nothing is logged: the queue just stops, every new session in every workspace sits in `starting`, and the 10-minute zombie reaper force-fails each one with the generic "launch stalled" message. The database looks idle (the server side of the dead connection is gone), and the agent-server looks healthy (it simply receives nothing), so every component checks out in isolation.
- **When to check**: Any in-process worker loop (`setInterval` + a `running`/`busy` flag, a single-flight mutex, a serial job runner) whose body awaits I/O — DB, HTTP, S3. Ask: if one await in here never settles, does the loop stop for everyone?
- **Fix pattern**: Bound the whole batch, not just individual calls: race it against a timer and release the flag when the timer wins, letting the hung promise continue detached (with its rejection swallowed). Per-call timeouts are still worth adding but cannot be the only guard — `postgres.js` has no client-side query timeout, and a server-side `statement_timeout` does not help when the connection itself is dead. See `tickTimeoutMs` in `apps/dev/src/services/session-dispatch-queue.ts`. Diagnose a suspected freeze by the queue's own silence: `session_dispatch_attempts` rows all `pending` with `next_attempt_at` hours in the past and no `Session dispatch …` log lines.
- **History**: 2026-09-29, production. The app restarted at 09:07:52 UTC for a frontend-only deploy (#1742); the queue ran for ~90s and then went silent at 09:09:28 UTC. For ~5.5h every session in every workspace failed with `startup_stalled` (164 rows stranded in the queue) until the app was restarted. Fixed by adding the tick-level timeout.
