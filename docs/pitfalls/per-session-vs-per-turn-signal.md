# A Per-Session Lifecycle Signal Driving Something That Is Really Per-Turn

- **What**: An interactive (chat) session stays `running` for its whole life and serves many turns, so session lifecycle events (`session_started`, `session_completed`, ...) fire once, at the edges, no matter how many turns the agent answers. Anything the user perceives as "the agent is working now" — an iOS Live Activity, a typing indicator, a "working" badge — therefore cannot be keyed off session start/end: wired that way it starts once, never ends between turns, and either sits on screen for hours after the agent has gone idle or never appears for the second and later turns. Nothing errors; the events arrive and are handled correctly, they just describe the wrong unit. Because the sender is mocked in unit tests, a test that feeds `session_started` / `session_completed` passes against exactly the broken model.
- **When to check**: Any feature that shows progress or presence for an agent and is driven by `events` rows with `entity_type: 'session'`, or by `sessions.status`. Ask: is this per session or per turn, and does the session type matter (interactive vs. one-shot)? Also whenever a lifecycle has a local (Docker) and a remote (dispatched) launch path — confirm the per-turn signal is emitted from the one place both paths share rather than from either launch path.
- **Fix pattern**: Drive it from an explicit per-turn signal. `SessionManager.writeInput()` emits `'turn'` `{ phase: 'started' }` after the user envelope is persisted, which is shared by the local and remote delivery branches; `onTurnFinished` on the finalizer emits `{ phase: 'finished', outcome }` once the closing message is posted. `LiveActivityPush` (`apps/dev/src/services/live-activity-push.ts`) subscribes to `'turn'` for interactive sessions, ignores their session-level start events, and keeps session-level end events only as a no-op safety net. Cover it with a test that runs two consecutive turns in one session and asserts start/end fire for each.
- **History**: Caught as a design constraint of the iOS Live Activity push work on `apple/integration-chat-parity` (`live-activity-push.ts` header comment); the turn-driven fan-out was built in from the start rather than found in production, so there is no incident or PR to cite yet.
