# A Bare `return` in a Shell Function Under `set -e` Aborts the Whole Script Silently

- **What**: In bash, `return` with no argument returns the status of the last command that ran. So `[ "$FLAG" = "1" ] || return` — an early exit for an optional feature — returns **1** whenever the flag is off, because the last command was the failed test. `docker/agent-base/agent-run.sh` runs under `set -eo pipefail` (line 2), so a bare call to that function aborts the script right there. The agent never starts, nothing is logged beyond the last `[system]` line before the call, and the session ends with `exit_code: 1` about 15 seconds after boot — indistinguishable from an auth or rate-limit failure, which is where the first diagnosis went. The trap is that the code is only broken **when the new feature is off**, which is every session that does not use it. The author's own tests (flag on) pass, the proxy or helper works perfectly when exercised directly, and the review reads as correct. A kill switch that works by turning the flag off, such as `MASKIN_TEXT_ONLY_MODELS=none`, lands on the same broken path, so it does not roll the change back.
- **When to check**: Any new or edited function in `docker/agent-base/*.sh` (`agent-run.sh`, `entrypoint.sh`, helper scripts), or any script that runs under `set -e`, that has an early exit for an optional feature (`[ ... ] || return`, `[ ... ] && return`, `cmd || return`). Also any function whose **last** statement is an `&&` list: when the test is false the list returns 1 and the function returns 1. Also any change to a startup path that every session takes — ask what a session that does not use the new feature does.
- **Fix pattern**: Write `return 0` explicitly for every early exit that means "nothing to do" (see `assert_skills_symlink` and `setup_strip_images_proxy` in `agent-run.sh`). Then exercise the **off** path, not just the on path: `scripts/checks/agent-image-smoke.sh` builds the real agent-base image, runs it through its real entrypoint with a stub `claude`, and covers the unflagged, bare-environment and flag-without-config cases; CI runs it as the `agent-image-smoke` job on any PR that touches `docker/agent-base/`. A new optional feature in `agent-run.sh` needs a case added to that script. Reading the script is not verification: this bug survived a careful review and 16 green checks, and was visible in under a minute of running the container.
- **History**: PR #2070 ("Strip image blocks for text-only models") added `setup_strip_images_proxy` with `[ "$MASKIN_STRIP_IMAGES" = "1" ] || return` and merged 2026-10-14 00:38 UTC. `MASKIN_STRIP_IMAGES` is only set for the deepseek `maskin_plan` route, so every `claude_oauth` session in every workspace exited 1 on boot from the first dispatch on the new image until the fix in PR #2082 was deployed — several hours; the Vaerksted workspace's agents, including the ones that would have run the post-merge check, all failed. The review had tagged the PR HIGH risk, recorded "agent-run.sh startup path inside a real container" as unverified, and deferred it to a post-merge real-route check run by an agent session on the same platform, which could not run once the platform was down. The `agent-image-smoke` CI job was added afterwards; with the bug reintroduced it fails on the first case.
